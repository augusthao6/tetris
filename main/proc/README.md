## Description of Design
I built a 32-bit 5 stage pipelined processor, implementing the specific ECE350 ISA. The pipeline follows the Fetch --> Decode --> Execute --> Memory --> Writeback structure, complete with bypassing and stalling. We build our components, following the diagrams provided in the slides.
Fetch:
We use a PC register that drives address_imem to fetch the current instruction. We increment PC by 1 each cycle for our word oriented. The next PC value is selected by the PC mux in the Execute stage and written on the falling edge. The F/D latch captures fd_insn, the raw instruction word from q_imem, and fd_pc_plus1, the incremented PC used for jal return address and branch target calculation. If a flush is in progress, fd_insn is forced to 32'b0, a NOP. If a stall is in progress, the F/D latch's input_enable is deasserted, freezing both fields in place.
Decode:
We decode fd_insn into opcode and the necessary registers/values for a specific instruction based on its type: R, I, JI, JII. ctrl_readRegA and ctrl_readRegB select which registers to present to the register file's two read ports based on the specific instruction in order for it to work in Execute. The D/X latch captures the instruction, PC+1, and both register read values data_readRegA, data_readRegB. These are later superseded by bypass if a hazard exists. When a load-use stall fires, dx_insn_in is forced to 32'b0, basically inserting a NOP bubble at the head of Execute. Same when a pipeline flush fires.
Execute:
Execute does a lot of things. It computes the ALU operation, receiving data inputs and performing operations based on alu_opcode, subtract for bne and blt, and add for addi and lw, sw address calculations. It also resolves branch and jumps. bne when ALU reports isNotEqual, blt when ALU reports isLessThan. bex taken when $r30 != 0. The branch target is computed by a separate adder on PC+1+sign_extended_offset. For not taken branches, no flush occurs and the speculatively fetched instructions continue normally. j and jal redirect to the target. jr redirects to the register value after forwarding. jal additionally writes PC+1 to $r31 via the normal writeback path, so jr $r31 immediately after gets the correct return address via the XM bypass. Since branches and jumps resolve here, two speculatively fetched instructions always sit behind them in F/D and D/X. When a branch is taken or any jump fires, both are flushed by zeroing out F/D and D/X. The !stall guard on flush_pipeline prevents a flush from firing while the pipeline is frozen, but if both happen at once, the stall takes priority and the flush happens naturally the next cycle. The PC mux priority matters a lot and it goes stall --> jr --> bex --> branch --> j/jal --> PC+1. The ALU also calculates overflows and $rstatus based on values provided in the doc, overwriting the data and location if detected. The X/M latch captures the ALU result xm_alu_out, the bypassed store data xm_storedata, destination register xm_rd, and control signals xm_regwrite, xm_sw, xm_lw.
Memory:
address_dmem is driven directly by xm_alu_out, the computed load/store address. data is driven by xm_storedata. wren is asserted only when we are storing, or xm_sw. For load instructions, q_dmem is used in the XM bypass, when lw is in X/M and the immediately following instruction is in Execute, q_dmem is forwarded directly as xm_bypass_val = q_dmem, or the MW bypass path and writeback, where we latch a register to capture q_dmem on the falling edge so it is stable during Writeback, whatever address the next instruction may be driving. The M/W latch captures xm_alu_out, mw_dmem, mw_rd, mw_regwrite, and mw_lw.
Writeback:
We calculate mw_writedata = mw_lw ? mw_dmem : mw_alu_out and write it correctly using data_writeReg, ctrl_writeReg, and ctrl_writeEnable to the register file. The write enable is also gated on mw_rd != 5'd0 so we never overwrite $r0.

## Bypassing
Bypassing follows as shown in the slides. The idea is routing a result from a later pipeline stage back to the Execute stage inputs before it has been committed to the register file, fixing read after write (RAW) data hazards. We implement XM bypass, where the result is 1 cycle old and the producer is in X/M, and MW bypass, where the result is 2 cycles old and the producer is in M/W. XM bypass — result is 1 cycle old (producer is in X/M). 
For XM bypass, we get the value in xm_bypass_val as either q_dmem for a lw because the load address has been stable for a full clock cycle and memory has had time to respond, or xm_alu_out since the ALU result was captured after the instruction left execute. 
For MW bypass, mw_writedata is mw_dmem for lw, a capture of q_dmem captured when the load was in X/M, or mw_alu_out. We use mw_dmem and not q_dmem because for example with two consecutive loads, the first in M/W and the second in X/M, q_dmem would use the second load's address and data. This was very important and caused me a lot of trouble. Both bypass paths are active only when the producing instruction genuinely writes a nonzero register. Also, XM takes priority over MW. If both stages have written the same register, for example two consecutive writes, the XM value is more recent and therefore correct.
Also, the bypass comparisons must use the correct architectural register number for each port. The mapping depends on the instruction type currently in Execute, and mirrors the Decode-stage register select logic exactly. Every place in Execute that reads a register value uses the bypassed result, not the raw D/X latch read. This is used in both ALU inputs, branch comparisons bne and blt, bex condition, jr target, sw store data, and mul/div operands. This also helps bypass specific scenarios such as setx immediately followed by bex, jal followed by jr $r31, overflow exceptions followed by a $r30 read, and multdiv results.

## Stalling
Stalling is when we freeze the PC and F/D latch in place and use a NOP "bubble" in D/X so that we complete an additional pipeline stage before the dependent instruction proceeds. We looked at two types of stalls, a load-use hazard and mult/div when in progress. 
The load-use stall is when you have a lw in D/X and the instruction immediately after needs the loaded register in its own Execute stage. Since lw gets its result from data memory a full clock cycle after the Execute stage, we need to add a stall, or NOP bubble. We freeze by using !stall, and insert a bubble into our DX registers using 32'b0. X/M and M/W latches advance regardless.
The multdiv stall is used to correctly calculate multiply and divide, and prevent any write after write (WAW) errors. We have an iterative unit that takes a varying number of cycles to complete, so the entire pipeline stalls for the duration. So we check if the operation is running using a flip-flop doing_multdiv, we calculate doing_multdiv_next, and we stall if (doing_multdiv && !multdiv_ready) || (dx_multdiv && !doing_multdiv). During a multdiv stall, we make the D/X latch's input_enable = !stall_multdiv to hold the instruction in place, and the multiplier runs in the background. When multdiv_ready asserts, dx_writedata = multdiv_out and the stall releases, allowing the result to flow into X/M.
We use stall = stall_multdiv || stall_lw, which is used in PC and F/D hold logic because they are the same.

## Optimizations
Forwarding using XM and MW bypass eliminates a lot of stalls, covers distances of 1 or 2 cycles for all instructions. 
One optimization is we don't stall for lw --> sw. We don't actually need to stall because the store data doesn't need to available at the start of Execute, and is latched into xm_storedata during Execute and used in memory one cycle later. We implement this in our stall_lw as a case (dx_rd == ctrl_readRegB && !fd_sw). 
Also, we register q_dmem, which is used by mw_dmem to capture as a load transitions from XM to MW. Without the register, consecutive loads would read the wrong value in the MW bypass because q_dmem would be driven by the second load's address.
Branches resolve in Execute instead of memory, so we flush 2 cycles instead of 3.
Finally, we never ever allow instructions to write to $r0, and we suppress that everywhere.
